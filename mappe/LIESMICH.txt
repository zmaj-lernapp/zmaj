SO ENTSTEHT DAS WORD-DOKUMENT DER PROJEKTMAPPE
==============================================

Der Text steht in den Kapiteldateien, das Layout in bauen.js. Getrennt,
damit sich am Text etwas ändern lässt, ohne das Layout anzufassen – und
umgekehrt.


Was hier liegt
--------------
  kapitel1.json       Kapitel 1 – und außerdem die Titelzeilen, der Stand
                      für die Fußzeile und die ganze Gliederung mit den
                      Seitenzahlen fürs Inhaltsverzeichnis.
  kapitel2.json       Kapitel 2, das Lastenheft.
  kapitel3.json       Kapitel 3, die Konzeptfindung.
  kapitel4.json       Kapitel 4, die Risikoanalyse.
  kapitel5.json       Kapitel 5, die Projektdurchführung.
  anhang_quellen.json Abschnitt 6.1, die Belegstellen zu 2.2.

  bauen.js         Baut daraus die Word-Datei. Layout, Schriften, Fußzeile.
                   Fehlt eine der Kapiteldateien, wird sie übersprungen –
                   das Dokument entsteht dann ohne dieses Kapitel.
  pdf2png.ps1      Macht aus einem PDF Bilder, eine je Seite. Damit lässt
                   sich das Ergebnis wirklich anschauen, nicht nur der Text
                   prüfen. Nutzt den PDF-Renderer, der in Windows steckt –
                   es muss nichts installiert werden.
  zeiterfassung.js Rechnet die Stunden für 5.6 aus den Sitzungsprotokollen
                   neu und sagt, welche Zahl in kapitel5.json nicht mehr
                   stimmt. Vor der Abgabe einmal laufen lassen.

  Zmaj Projektmappe.docx   Das Ergebnis.


Neu bauen
---------

1. Einmalig die Pakete holen (braucht Internet):

      cd mappe
      npm install docx

   Der Ordner node_modules entsteht dabei und bleibt außen vor – er steht
   in .gitignore.

2. Bauen:

      node bauen.js "Zmaj Projektmappe.docx"


Ansehen, ohne Word zu öffnen
----------------------------

Word kann das Dokument selbst in ein PDF verwandeln, auch ohne dass ein
Fenster aufgeht. In PowerShell:

    $w = New-Object -ComObject Word.Application
    $w.Visible = $false
    $d = $w.Documents.Open("<voller Pfad>\Zmaj Projektmappe.docx", $false, $true)
    $d.SaveAs2("<voller Pfad>\Zmaj Projektmappe.pdf", 17)
    $d.Close($false); $w.Quit()

Und daraus Bilder:

    powershell -File pdf2png.ps1 -Pdf "Zmaj Projektmappe.pdf" -Ziel bilder -Breite 900


Die Seitenzahlen im Inhaltsverzeichnis
--------------------------------------

Sie stehen von Hand in der Gliederung in kapitel1.json, im vierten Feld
jeder Zeile. Ein leeres Feld wird zum Strich – so sieht der Betreuer, was
noch entsteht.

Nach jeder größeren Textänderung verschieben sie sich. Nachsehen lassen
sie sich mit Word selbst, ohne sie abzuzählen:

    foreach ($par in $d.Paragraphs) {
      if ($par.Range.ParagraphFormat.OutlineLevel -le 2) {
        "$($par.Range.Information(3))`t$($par.Range.Text.Trim())"
      }
    }

Danach die Zahlen in kapitel1.json eintragen und noch einmal bauen.


Am Text schreiben
-----------------

In jeder Kapiteldatei ist ein Abschnitt ein Eintrag unter "kapitel1",
"kapitel2" und so fort:

    { "ueberschrift": "1.5 Titel",
      "bloecke": [
        "Ein ganz normaler Absatz.",
        { "punkte": ["erster Punkt", "zweiter Punkt"] },
        { "mix": ["Text mit ", ["fettem Stück", true], " darin."] },
        { "tabelle": {
            "breiten": [20, 80],
            "mitte":   [0],
            "kopf":    ["Spalte", "noch eine Spalte"],
            "zeilen":  [["a", "b"], ["c", "d"]] } }
      ] }

Ein **doppelter Stern** macht ein Stück fett, auch mitten im Absatz.

Zur Tabelle: "breiten" sind Prozent und müssen 100 ergeben; fehlen sie,
werden alle Spalten gleich breit. Zellen, die nur aus Zahlen bestehen
("3", "1 bis 4"), werden von selbst zentriert – "mitte" zentriert weitere
Spalten, etwa eine mit Kennungen wie R3. Die Kopfzeile wiederholt sich,
wenn die Tabelle über einen Seitenwechsel läuft.

Mehr Formen gibt es absichtlich nicht. Eine Projektmappe braucht Absätze,
Aufzählungen, Tabellen und gelegentlich ein fettes Wort – alles andere
lenkt ab.

Umlaute und Anführungszeichen kommen direkt in die Datei, nicht als \u-Code.
Die eine Ausnahme ist das schließende deutsche Anführungszeichen: Es muss
als “ geschrieben werden, weil " in JSON den Text beenden würde.


Die Zahlen in 5.6 wandern
-------------------------

Die Zeiterfassung wird aus den Sitzungsprotokollen abgeleitet, und die
wachsen weiter, solange am Projekt gearbeitet wird. Jede Zahl dort ist
also ein Stand, kein Endwert:

    node zeiterfassung.js

Das Skript liest die Protokolle unter %USERPROFILE%\.claude\projects,
rechnet Stunden, Pausenschwellen und Lücken neu und vergleicht das
Ergebnis mit dem, was in kapitel5.json steht. Es ändert nichts von
selbst – es sagt nur, was nicht mehr stimmt.

Dass die Zahl der Zeitstempel schon nach wenigen Minuten abweicht, ist
normal: Die laufende Sitzung schreibt ja weiter mit. Was zählt, ist der
Stand in der Fußzeile.


Verweise zwischen den Kapiteln
------------------------------

Ein Kapitel wiederholt nicht, was ein anderes schon sagt, sondern nennt den
Abschnitt: "Der Betrieb ohne Server ist in Abschnitt 2.3 beschrieben."
Wer einen Abschnitt umnummeriert, muss die Verweise mitziehen. Finden lassen
sie sich so:

    grep -o "Abschnitt [0-9.]*" *.json | sort | uniq -c
